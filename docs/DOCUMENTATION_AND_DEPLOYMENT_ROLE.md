**Unichild International School Website and Student Information Management System**

**Repository:** `niipascal51-tech/unichild-international-school_webproject`

## Role purpose
Maintain clear, accurate, and traceable project documentation; keep repository documentation organized; support release preparation and deployment; and preserve evidence of the work completed.

## Responsibilities
- Maintain `README.md`, `TEAM.md`, and relevant files under `docs/`.
- Keep the project name, team name, repository reference, and status consistent across documents.
- Preserve the client's original Master Project Requirements as the requirements baseline.
- Link requirements and user stories to GitHub issues, pull requests, reviews, and tests where applicable.
- Document setup, testing, deployment, known limitations, and handover instructions using verified facts.
- Review documentation links and Markdown formatting.
- Coordinate with developers before documenting environment variables, commands, or backend deployment details.
- Keep screenshots and test evidence genuine and dated where appropriate.
- Avoid exposing secrets, credentials, private student records, or other confidential information.
- Record personal AI-assisted contributions accurately in the team's AI usage log and follow the agreed review policy.

## Suggested completion evidence
For each task, retain evidence such as:
- GitHub commit or pull-request link.
- Screenshot showing the committed file or workflow result.
- Actual command output for setup, linting, or testing.
- Verified deployment URL and deployment status, if deployment is completed.
- Reviewer feedback or client acceptance only when genuinely received.

## Definition of done
A documentation task is done when:
1. The content is accurate and matches the current project.
2. The file is saved in the agreed repository location.
3. Links and Markdown formatting have been checked.
4. Changes are committed and reviewed according to the team's workflow.
5. Claims about functionality, tests, deployment, and client acceptance have evidence.
6. The related GitHub issue is updated truthfully.
