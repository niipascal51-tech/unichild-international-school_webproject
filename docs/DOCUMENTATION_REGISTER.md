# Documentation Register

This register lists expected documentation and the evidence needed to confirm each item. Update statuses after inspecting the repository.

| Artifact | Suggested location | Purpose | Status |
|---|---|---|---|
| Project README | `README.md` | Overview, scope, setup, testing, links | Added according to progress report; verify |
| Team information | `TEAM.md` | Team members and roles | Being added; verify |
| Contribution guidance | `CONTRIBUTING.md` | Branching, commits, reviews, tests | Inspect/create if missing |
| Project documentation overview | `docs/PROJECT_DOCUMENTATION.md` | Scope and documentation overview | Added according to progress report; verify |
| Role responsibilities | `docs/DOCUMENTATION_AND_DEPLOYMENT_ROLE.md` | Documentation/deployment ownership | Add to repository |
| Deployment guide | `docs/DEPLOYMENT_GUIDE.md` | Deployment procedure and evidence | Add to repository |
| Testing checklist | `docs/TESTING_CHECKLIST.md` | Manual test evidence | Add to repository |
| Client Master Requirements | Keep original in approved project records | Requirements baseline | Preserve original; do not replace with summary |
| D1 Project Proposal | Approved course/project location | Proposal and rationale | Verify final version |
| D2 SRS | Approved course/project location | Requirements baseline | Verify final version |
| D3 Product Backlog | Approved course/project location | Stories and acceptance criteria | Verify final version |
| AI-use policy | `AI_USAGE.md` | Rules for responsible AI use | Inspect |
| AI-use log | `AI_USAGE_LOG.md` | Individual AI-assisted work records | Inspect for accuracy and placeholders |
| Test evidence | `docs/` or agreed evidence folder | Actual results, defects, screenshots | Add after tests |
| Release/handover record | Agreed final documentation folder | Final hash, URL, known limitations, handover | Complete at release |

## Review rules
- Do not create duplicates if an equivalent approved document already exists.
- Use one consistent project title and canonical repository URL.
- Keep the client's original requirements intact.
- Do not invent test results, deployment URLs, client acceptance, commit hashes, or dates.
- Keep sensitive student information and secrets out of public documentation.
